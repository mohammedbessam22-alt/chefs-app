# chefs-app Backend (Medusa) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Medusa v2 backend + admin that holds the catalog and two-warehouse stock, accepts cash-on-delivery guest orders from the phone app, and gives staff confirm / deliver / cancel, round filters, packing lists, delivery settings and 4-language product text.

**Architecture:** Stock Medusa v2 (products, regions, carts, orders, stock locations, manual payment, admin) plus four small custom pieces: a `delivery_settings` module, a `translations` module, an `order.placed` subscriber that stamps orders with confirmation/round metadata, and admin API routes + admin UI pages under the `chefs` prefix. A scheduled job auto-cancels unconfirmed orders.

**Tech Stack:** Medusa v2 (latest at scaffold time), TypeScript, PostgreSQL 16, Redis, Jest (`@medusajs/test-utils`), Node 20.

**Spec:** `docs/superpowers/specs/2026-10-30-grocery-delivery-app-design.md`

## Global Constraints

- Single seller, one city (Kirkuk), region "Iraq", country `iq`, currency `iqd`, prices are whole IQD (no decimals).
- Cash on delivery only: Medusa built-in manual payment provider `pp_system_default`.
- Two shipping options: `Regular` and `Express`, flat prices editable in admin. Seed placeholders: Regular 2000, Express 5000 IQD.
- Two stock locations: `Warehouse A`, `Warehouse B`. Each product's inventory lives at exactly one location.
- Order confirmation states (in `order.metadata.confirmation`): `awaiting` → `confirmed` → `delivered`; `cancelled` from `awaiting` or `confirmed`. Totals may only go down after placement (staff use Medusa's built-in order edit to remove items).
- Auto-cancel `awaiting` orders older than `auto_cancel_minutes` (default 120).
- Locales: `ar` (base, stored on the product itself), `ckb` (Kurdish Sorani), `tk` (Turkmen), `en`. Missing translation → Arabic.
- Business timezone: Asia/Baghdad, fixed UTC+03:00 (no DST). Server clock is UTC.
- No connection to the POS. On the server: Redis DB index 1 (prod) / 2 (staging), never 0; port 9000 (prod) / 9100 (staging) bound to 127.0.0.1.
- Repo layout: `apps/backend` is an independent npm project (no root workspaces).

## Review Focus

1. An order placed exactly at a round's cut-off, or after the last round of the day, must join the **next** round (next day's first round after the last). → Task 3 tests.
2. Checkout with a quantity larger than stock must fail at cart completion, not create an order. → Task 4 test.
3. Staff pressing Confirm on an order the auto-cancel job just cancelled must get a 409, not resurrect it. → Task 5 test.
4. The auto-cancel job must never touch `confirmed`/`delivered` orders, or `awaiting` orders younger than the limit. → Task 6 tests.
5. A shop WhatsApp number typed as `0770 123 4567` must be stored as `9647701234567` (wa.me format); garbage must be rejected. → Task 3 test.
